# 17 例累计导入与扩展 12 例浏览器验收

本次使用独立 Playwright CLI 会话 `s17-expansion-contract`，持久配置目录为 `.playwright-cli/profile-expansion-contract`。不读取用户 Chrome 会话，不与主智能体的两套助手验收浏览器共用存储。

执行脚本为 `checks/browser-expansion-suite.mjs`。每一例保留单独 JSON 报告，实际下载保存于 `output/exports/v1.7/`。报告中的 `passed` 只计已经在浏览器中执行的断言。下载后的协议与散列检查另存报告，并明确属于 Node 文件验证。

验收顺序：

1. 在原站 `portal-original/index.html` 点击真实“＋ 添加案例”，通过目录输入与“校验并添加”导入 12 例扩展包及 5 例录井包。逐次确认没有“仅本次有效”提示，再刷新确认注册版本。
2. 从原站打开扩展案例的专业背景、流程与内嵌演示。实际查看背景 SVG；有流程步骤按钮的逐个点击，无步骤按钮的逐图滚动并确认可见。两者在报告中分别记录，不把静态图册写成步骤按钮交互。
3. 在演示中实际计算、修改输入使结果过期、重算、重置、填写人工意见，并通过真实下载事件保存 JSON。刷新原站后再次运行，比较默认指标。
4. 真正关闭 CLI 浏览器，使用同一持久配置重新打开；确认 17 例仍注册，再运行所选案例。
5. 每个新案例以 `file:///` 打开，并在浏览器上下文禁网状态下运行，检查助手本地导览和页内流程导航。记录 HTTP 请求，实际窄屏 390 × 844 检查正文、溢出和按钮可达性。
6. 导入老师提供的 `firstbreak-pick-case`，等待原上传器 620 ms 延时跳转完成，再切到演示并改变控件。

所有构建版本需由父智能体发出 `BUILD_READY` 后才能锁定最终结果。第一次导入容量探测之后发现扩展页字体受旧共享 CSS 覆盖，父智能体修复并重新构建；第一次结果保留为 `browser-import-before-readability-fix.json`，不作为最终版本通过证据。
