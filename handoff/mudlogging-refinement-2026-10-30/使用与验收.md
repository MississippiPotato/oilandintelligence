# 录井案例智能化呈现修改与验收

日期：2026-10-30。范围为增强门户和 M1—M5 五个录井案例，纯前端；老师原门户目录和原始资料副本均未改动。当前结果在本地工作区，未推送或发布到 GitHub Pages。

## 打开与重建

- 本地增强门户：双击 `portal/index.html`，或者在项目根目录运行 `node tools/serve.mjs` 并访问 `http://127.0.0.1:8755/portal/index.html`。如该端口已在使用，请先检查现有服务。
- 单个离线案例：双击 `dist/cases/<案例ID>/demo/index.html`；每个目录都是老师原门户可识别的五文件案例包，需完整保留 `case.json`、`README.txt` 和 `demo` 下三个文件。
- 老师原门户已导入同一 ID 的旧案例时，需要先在原门户案例库中移除旧案例，再导入对应的新文件夹；它不会自动用本地文件覆盖已经存储在浏览器内的旧包。
- 增强门户的五个案例是内置内容，不需要通过老师原门户的“添加案例”依次导入。其他 56 个扩展案例未重建。
- 如以后再改 M1/M3/M4/M5 的计算或讲解源码，先运行 `node tools/build-mudlogging-refinement.mjs --allow-stale-preview`，启动本地服务和 Playwright CLI 会话后，以环境变量 `S17_FLOW_BASE_URL=http://127.0.0.1:8755` 运行 `node tools/capture-four-flow.mjs`，最后执行 `node tools/build-mudlogging-refinement.mjs`。这一步用实际浏览器生成四个默认静态流程预览，并且只更新五个录井案例及增强门户对应正文。M2 静态预览由构建时真实计算生成。

## 各案例的修改

- M1 岩屑：演示开头展示检出颗粒数、可见总面积、选中颗粒的近邻候选和支持度，可跳到近邻与整盘统计；流程中保留实际近邻图，并增加按全部 k 个近邻计算的各类加权票数。
- M2 气测：演示开头展示当前气峰的 kNN 候选、支持度和核查提醒；流程将峰宽、组分变化和来源工况的实际标准化值可视化，列出近邻及加权投票，说明图上的总气曲线只是多维距离的一部分，6 维与 11 维模型的距离不可跨模型直接比较。
- M3 荧光：演示开头显示逻辑回归的检出像素、共同分母和比例；流程图展示当前像素各特征对逻辑回归得分的实际正负贡献、基础项、sigmoid 得分及阈值，保留白光/紫外图和方法比较。
- M4 钻时：演示开头对照基线与模型候选数、显示有效连续段数量；流程明确岭回归标定、两维响应、k-means 中心和距离、连续分段及核查。工况开关的文字明确只切换钻速响应的工况校正，扭矩响应始终保留固定修正。算法在非钻进缺口两侧分别做连续性优化和短段合并，不把缺口当成候选界面。
- M5 报告：演示开头显示当前句子的朴素贝叶斯栏目候选、报告句数及核对进度；流程在六类相对分数旁展示真实词项贡献，并说明数字归一化。常见荧光肯定/否定用语、气测起止读数及单位得到保留，不能唯一判断的原文与数值会标为待核查；端点相接的井段不作为重叠，无单位气测值不被直接判为可比较的冲突。M4 上游快照重新运行并提升来源版本，仍明确是构建期快照。

## 验证与边界

- `npm test`：1168 项源码、成品和索引检查通过，覆盖 65 个案例和 325 个运行文件；不代表 65 个案例的浏览器全路径验收。本次授权调整的三处原冻结文件使用新旧哈希对照，其余仍按原锁检查；新检查结果保存在本目录，历史锁未改写。首次运行曾被旧的冻结规则挡住，更新检查规则并完成对应新哈希核对后通过。
- `node checks/verify-mudlogging-refinement.mjs`：通过 M4 缺口隔离、无缺口界面、孤立点/空段，以及 M5 肯定、否定、未知、起止值、多值歧义、单位、端点和混合表述的定向回归。
- `node checks/verify.mjs --no-write`：14 项通过。
- `node checks/verify-mudlogging-artifacts.mjs`：五个包均为五文件，静态流程预览与源码哈希一致，增强门户五份正文及目录与当前构建一致；老师原门户与原始资料副本的 23 个锁定文件逐个匹配。
- 增强门户：五个案例的流程步数（M1—M4 各 6 步，M5 5 步）、默认 `#lab` 入口、结果卡片和一次条件变化后的重算通过；移动端额外检查 M3 页面。截图与数据见 `browser-portal-final.json` 和 `output/playwright/mudlogging-refinement-*`。
- 独立案例：Chrome 实际打开五个 `file://` 页面并使浏览器离线，每例默认计算和一次输入修改后的重算均通过，未发出 HTTP 请求；见 `browser-offline-final.json`。增强门户 `file://` 离线仅抽查 M2/M3，见 `browser-portal-file.json`。
- 老师原门户：五例分别验证目录导入、全部静态流程步骤、刷新及改变条件重算；M4/M5/M1/M3 在一次连续导入中通过，M2 在独立浏览器中通过，M5 末次修改后也另行通过。不是五例同时保存通过。
- 原门户原有的 `localStorage` 容量有限。实际测试先保存四个案例后再添加 M2，门户提示“仅本次有效，刷新后会丢失”，刷新后该案例确实不在存储列表中；原先版本的五个案例包大小已经超过这一累计容量。证据见 `browser-teacher-storage-limit.json`。这是保留原门户只读兼容副本时的限制，增强门户内置案例不需要占用这些导入存储。
- 历史检查 `node checks/verify-mandatory.mjs --no-write` 中 13 项通过，1 项以旧版 `handoff/build-lock.json` 的文件哈希检查本次有意更新的成品而失败；没有把旧锁文件改写成当前结果。当前产物使用本次 `build-lock.json`、`m2-build-lock.json` 及 `artifact-verification.json` 核对。
- 教学数据、阈值和分类结果用于解释方法，不能当作现场模型验证或油气发现。M5 的抽取是有限规则，不支持的说法仍需人工核查；近邻支持度不是经过现场校准的概率。
