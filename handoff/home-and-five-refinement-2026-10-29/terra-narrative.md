# 五个录井案例：连续阅读与知识可视化建议

日期：2026-10-29。范围：m1–m5 的教学叙事、流程和画卷；不改动计算引擎、原始数据、门户助手或其他 56 例。本文是针对当前源码的实施建议，不代表修改或验收已完成。

## 优先实施

1. 保留“专业背景／案例流程／可运行示范”三个入口，使其成为页内定位，三个部分和内部章节沿同一页面连续可读。以一个样品、气峰、井段或子句贯穿，取消读几段便必须切换的中断。
2. 流程每一步只出现一次名称，紧接一行“输入 → 动作 → 产物”，产物旁就是对应的图或实际读数。取消“步骤箭头 + 六个大按钮 + 再重复步骤标题”的三重呈现。5/6 步使用一致的纵向步骤行，避免第六格被迫全宽；窄屏直接纵排。
3. 现有背景已经有不少知识内容。本轮把 2–3 处最能解释关系、变化和方法价值的现有图放到读者需要它的段落附近，调整图注和控制入口；不要为了显得丰富增加同义解释或重复图。
4. 画卷保持适中尺寸。沿既有图片的工作区域建立轻边界，选择区域后以平面剪影上移、轻微放大和投影模拟纸本抬起，其余区域轻微减淡。点击先保留选中反馈，旁边另有“阅读这一部分”定位正文。
5. 把适用范围自然写进图例、单位、图注与“下一步看什么”，删除与阅读动作无关的反复自辩文字；数据来源、真实/教学数据角色和必要的解释边界保留。

## 参考站：哪些形式真正服务了知识

在独立 Playwright 会话实际打开了 [参考仓库](https://github.com/cinger007/saphirv3)、[参考站首页](https://cinger007.github.io/saphirv3/) 和 [case-003](https://cinger007.github.io/saphirv3/case-003/)。实际切换了“专业背景／讲义／案例演示／专业练习”，载入演示数据并执行第一阶段，也在练习填入错误数值后点击自检。不是仅凭截图推断交互。

- case-003 的背景把“单井只给距离，多井共同约束位置”作为同一个问题，术语图用曲线、圆和联系线解释观测如何变成约束。每张图有“在专业中指什么”和“计算上对应什么”，因此图形承担解释，非插入一张论文图片。
- 讲义从应用问题、数据对象与判据出发，再讲三段分工，左侧目录跳到连续章节。可借鉴“专业问题 → 证据如何产生 → 何时能判断”的因果顺序，不必照搬其很多外层 Tab。
- 案例演示先列输入文件与字段，再展示阶段目的、动作和思考问题，按“执行”展开阶段产物和来源。我实际点开第一阶段后，阶段进度由 0/5 到 1/5，出现来源字段及“距离标量→位置与走向→解集”的图解。**该站页面注明数字由构建期归档结果读出，并未在页面重算模型**；本项目已有前端真计算，应保留实时引擎，只借用任务、动作、产物的讲解方式。
- 专业练习里，填 `0.5` 并自检后，页面给出“再想想”和计算依据；每步设目的、做什么、期望看到什么。这种就地反馈适合“先猜再改一个条件”。但其页面顶部与题目正文已经露出一些参考值，原样复制会削弱先判断后验证的效果；本轮不必新做一整套练习系统。
- 本次 case-003 页面控制台出现 3 条 polyline 点含 `nan` 的错误及 favicon 404。以上观察仅覆盖所述交互，不视为参考站完整功能验收。

## 连续结构与程序接线

建议每页：一句专业问题与当前对象 → 一幅可选择的场景画卷 → 四个连续背景章节 → 一张不重复的输入、动作、产物流程 → 一处贯穿对象的可运行示范 → 收束当前能说出的观察和下一步核对。每段都回答“这张图上看什么、为什么对判断有用”，在必要处才介绍方法名。

- 当前四例独立演示的生成入口是 `tools/build-four-exhibits.mjs`，交互入口是 `shared/four-exhibits.js`。`selectPart()` 现在对 `[data-fx-part-panel]` 使用 `hidden`；改成三个 section 都显示，`[data-fx-part]` 只定位 `#background`、`#workflow`、`#lab`。继续支持已有 hash，使用 `scroll-margin-top` 避让吸顶导航，并用滚动观察更新当前项；滚动观察不要反向触发新的滚动。
- m2 独立实现位于 `case-src/m2/exhibit.html`、`exhibit-ui.js`、`reading.js`、`presentation.js`、`tools/m2-exhibit-content.mjs` 和 `tools/build-m2-exhibit.mjs`；当前目录没有 `case-src/m2/app.js` 或 `case-src/m2/exhibit.js`。`showPart()` 当前隐藏另外两块，要同步改为定位。`M2Reading.flowStep()` 和 `M2Presentation.flowHTML()` 也默认一次仅见一步，要同步改成连续展示。
- 不应简单靠 CSS 覆盖 `[hidden]`：m1 的 `changeStage()`、m2 的 `showStage()`、m5 的 `setStage()` 实际修改面板显隐；需要修改这些显示逻辑并保持原对象、计算和重置状态。m3 的 `stage` 还改变 `paint()` 显示、曝光/方法区显隐；m4 的 `stage` 会改变 `tracksChart()` 的强调和提示。讲解章节连续呈现与图中“显示方式/当前阶段”是不同状态，应分别管理，避免导航误改图的数据模式。
- 四例 `drawFlow()` 每次只调用当前 `api.flowHTML(step)`；如果改为全步展示，默认计算后按顺序挂载 5/6 个产物容器，输入或对象更新后通过 `changed()` 让对应产物更新。m4/m5 的 `flowHTML()` 自带输入、动作或标题，渲染时只保留一处，避免外层再包一份同义字段。不要把完整 lab 节点复制多个有相同 ID 的副本。
- 运行态保持一个可信状态源：具体图尽量移动、复用现有节点，或给图表公开只读渲染接口后订阅同一 run；不要在几个章节各启一套互不相干的训练/模型状态。原门户中的 `case.json` 背景与流程是默认情景静态预览，独立演示页运行当前状态；两者分别标清，以免把预览误认作当前控制的结果。
- 老师原门户 `portal-original/assets/core/shell.js` 本身按背景、流程、示范 Tab 渲染，且先渲染 `workflow.steps` 再渲染 `metrics`。不改只读原门户的前提下，连续三段首先落实在完整示范页；清单仍保留四个背景 `sections` 与非空 `workflow.steps`，将 `metrics` 精简为与步骤互补的实际结果图，不再重复整套步骤标题。原门户导入、刷新、再运行和独立 `file://` 需分别验证。

## 五例：每例 2–3 个真正承载认识的图

下列图均复用现有计算或既有图；若重排到背景/流程，只做节点复用或明确的只读图表接口，不重复训练、计算或 DOM ID。每个图下只留一个“看哪里/试一次/看变化”的短提示。

### m1 岩屑：从一粒到一盘

主线：岩屑由井底返出 → 观察外观 → 当前轮廓如何变成特征和候选 → 一盘结果为什么有两个分母。背景的岩芯照片回答“真实岩石可观察什么”，教学盘负责可控识别实验。

1. **同盘像素 ↔ 实际分割轮廓。** `case-src/m1/exhibit.js` 的 `drawImages()` 画 `#m1-raw` 与 `#m1-outlines`；选择轮廓或 `[data-m1-grain]`，操作 `#m1-light`、`#m1-coating`、`#m1-preset`。问“改变照明或附着时，原位置的轮廓还在吗？”同时看参考片、质控和 `#m1-tracking`，不要把重排后同坐标说成同一物理颗粒。
2. **一粒的局部 ↔ 特征 ↔ 真实近邻。** `render()` 更新 `#m1-features`、`#m1-methods`、`#m1-neighbors`，`featureRows()` 提供颜色、纹理、形状，邻居来自实际训练库。选一粒后并排看局部、特征、前三近邻和颜色规则；无轮廓时保留原锚点并显示没有该对象的特征/近邻。
3. **数量与面积是两种权重。** `proportionsHTML()` / `M1Core.proportions()` 以同类颜色呈现“颗粒数”和“可见面积”带，明确分子、分母及待复核。选中粒子时用其 `1/检出数` 与 `自身像素/总可见像素` 对照，改变遮盖或靠拢后看两分母是否改变；不把二维面积写成地层质量或体积。

流程安排：样品登记和参考片校正接原图及实际灰片 RGB；分割接轮廓图；特征接当前局部；近邻与颜色规则接训练邻居；汇总接两种比例带。每一步输出承接下一步输入，6 个步骤无需六张大按钮。

### m2 气测：追踪同一个峰 A

主线：地面看到峰 → 沿循环回到来源时段 → 同一曲线加上组分与工况 → 比较邻居及候选。气峰、来源和工况应始终通过同一个时间坐标讲清关系。

1. **峰窗与组分。** `M2Figures.gas(rows,event,{components:true})` 按相同时间轴显示总气、C1–C3；检测版使用 `detectionThreshold`。选 `#event-picker` 的峰 A，阴影是当前实际检测窗口；小组分各有纵轴，读时间对齐而不是误比不同轨迹的高度。
2. **到达时刻 ↔ 来源时段。** `M2Figures.clocks()` 与 `#volume`、`#pause-flow`、`#correct-lag` 展示气峰、流量、累计体积和作业色带；打开停泵看累计量平台以及到达/来源连线变化。背景中 `[data-m2-bg-volume]`、`[data-m2-bg-pause]` 已通过 `M2Reading` 调用 `M2Presentation.calculate()`；若与 lab 并置，须明确它是独立演示设定，或改用同一状态源同步。
3. **同峰工况 ↔ 近邻解释。** `M2Figures.neighbors()`、`M2Presentation.comparison()` 和 `#context`、`#override` 显示相似事件、距离、支持度和规则。只切峰 A 的来源日志，气测逐点保持不变，比较候选如何改变；反事实没有评价金标，支持度为加权投票占比。

流程安排：观测和峰窗接气测图；迟到归位接双时钟；特征比较接实际特征数值；近邻/规则接邻居图；最后把来源记录、当前候选和下一步核查放在一起。输气延迟与泵送归位的不同作用在图注一句说明。

### m3 荧光：先对应位置，再比较面积

主线：同样品白光与 UV 看不同信息 → 曝光改变可能改变像素值 → 同一可见范围内比较掩膜和分子/分母 → 再核对发光来源。

1. **同一样品的空间对应。** 实验 `paint()` 更新 `[data-m3-canvas=white]` 与 `[data-m3-canvas=uv]`，点击任一点同步十字；真实方解石白光/短波/长波配对由 `readingMount()` 和 `[data-m3-real-mode]` 切换，帮助理解矿物也可能发光。真实方解石与教学盘分开说明。
2. **曝光与参考。** `[data-m3-exposure]` 从 1.0 改 0.5、2.0，再到 4.0，`recalculate()` 真正计算原始 UV、参考片、饱和数与质量信息；固定样品、白光和激发。优先让读者比较拍摄亮度改变与参考校正的效果，实际饱和提醒随运算显示。
3. **哪一些像素被选入，比例除以什么。** `paint()` 的掩膜、`render()` 的 `[data-m3-methods]` 和 `[data-m3-summary]` 联动 B0/B1/M0；`[data-m3-view]` 可切原图、叠加、得分、纯掩膜。三行同时写实际分子和共同可见范围分母，点像素看真实得分；得分是教学分割得分，不作含油概率。

流程安排：配对接白光/UV 图；曝光质控接参考数值；特征及得分接当前点；显示分割接掩膜；方法比较接三行分子分母；面积陈述接样品、曝光和来源核查。

### m4 钻时：一条共同深度轴解释变化

主线：一米钻多久 → 同深度对齐 ROP、WOB、RPM → 工况解释后剩下怎样的响应 → 连续分段及薄层会怎样变化。

1. **真实曲线的共同深度。** `realChart()` / `realReadout()`，配合 `[data-m4-real-index]` 和 `[data-m4-real-unit]`，展示真实 USROP 的 ROP 或钻时、WOB、RPM 三轨；一根游标同深度对齐并回到原行号，缺测跨度断线。真实曲线用于认识读图，不把教学标定或界面标签套到它上面。
2. **同一井段的原始值 ↔ 工况校正 ↔ 候选段。** `tracksChart()` 使用 `#m4-depth` 的共同游标，`#m4-normalize` 切工况校正，查看原始 ROP 不变而相对响应、预测及基线实际怎样变。解释里说“校正后的分段是否改变以实际计算为准”，避免预设必然改变。
3. **薄层厚度 ↔ 固定采样 ↔ 预测段。** `#m4-preset=thin`、`#m4-thickness`、`thinSamplingHTML()` / `thinSampling()` 列设计厚度、实际采样点与首末跨度，再与 `segments()` 的预测区间对照。采样间隔固定 0.25 m，厚度变了却落入同样采样点时结果可以相同；预测组编号不是岩性。

流程安排：有效记录/单位接真实轨迹；标定和相对响应接同深度数值；分组、连续分段接多轨图和候选界面；核查时叠加原始基线。不要把教学控制情景叠到真实曲线上当成实测模型输出。

### m5 报告：让同一句话在原文、字段、报告之间移动

主线：多种观察各自有井段/时段 → 一句原文中的范围、数值、单位、否定 → 分类与字段抽取是两种产物 → 报告句能回查并在修订后重新核对。

1. **原句 ↔ 字段的字符位置。** `fieldMarkup()`、`fieldItems()` 和 `[data-m5-example=negation|value|range]` 改动一个词、值或井段；原文标记和字段卡实时对应，查看“未见→见”改变观察，而栏目可仍为荧光。保留缺失和否定作用范围待核对的状态。
2. **同一子句的两条处理线路。** `scorePlot()` 显示 `[data-m5-scores]` 的六类相对对数分数与关键词基线；`[data-m5-fields]` 同时显示实际抽取字段；`[data-m5-contributions]` 可在需要时解释用到的字符。最高类为 0、其他为分差，不是概率。分流类别与事实完整分别检查。
3. **报告句 ↔ 当前原文版本。** `sourcePreview()` / `rangeSources()` 与 `[data-m5-report-select]`、`[data-m5-confirm]` 对应显示报告句、原文位置以及继承的范围来源；确认后改原文，旧确认失效。示意线应连接实际字符/句子，不画与事实无关的装饰网络。

流程安排：收集接原文；分句抽取接高亮字段；分类接真实分数；组装接报告句；核查接原文和确认状态。变更后的文本没有金标时不沿用默认文本评价。

## 画卷：五张图的区域、缩放与交互

五图 `scroll-selected.jpg` 均为 **2172×724，宽高比 3:1**。用一张原图作为 SVG `<image id="scene-image">`，通过 `<use>` 和 4 个带 `clipPathUnits="userSpaceOnUse"` 的多边形重用该图：一张底图轻微降饱和/亮度，选中区域的 `<use>` 裁切后 `translateY(-8px) scale(1.018)` 并加轻投影。轻边界可沿分区形状绘低对比细线，不画朱红矩形。底图仍在下方，所以这是二维切片的抬起效果，不称作真实三维重建。一个 image URI 被 defs 引用，避免把 base64 图片复制 4–5 次导致体积飙升。
